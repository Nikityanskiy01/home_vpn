# 7. Полный сценарий для новичка: что нажимать и что проверять

Эта глава — маршрут от пустого сервера до работающих SMART и FULL. Не спешите: после каждого шага есть проверка. Если проверка не прошла, **не переходите дальше**.

## Перед стартом: пять простых слов

| Слово | По-человечески |
|---|---|
| IP-адрес | адрес устройства внутри сети, например `10.77.30.1` |
| шлюз | устройство, куда клиент отправляет трафик «во внешний мир» |
| VLAN | отдельная виртуальная сеть на одном кабеле; номер 20 и 30 — её метки |
| bridge | виртуальный «коммутатор» Proxmox |
| fail-closed | VPN отключился — интернет блокируется, а не идёт напрямую |

## Карта действий

```mermaid
flowchart LR
 A[Записать адреса] --> B[Сделать backup]
 B --> C[Создать VM OpenWrt]
 C --> D[Настроить WAN и management]
 D --> E[Доставить VLAN 20/30]
 E --> F[Создать SMART/FULL и DHCP]
 F --> G[Firewall FULL: без выхода в WAN]
 G --> H[Nikki/Mihomo + подписки]
 H --> I[Тест SMART]
 I --> J[Тест FULL]
 J --> K[Отключить VPN и проверить kill-switch]
```

## Шаг 0. Выпишите данные на бумагу

Откройте [`../templates/параметры-сети.example.md`](../templates/параметры-сети.example.md), скопируйте его **за пределы репозитория** и заполните. Для исходного HomeLab известны такие значения:

```text
Keenetic:              192.168.1.1
OpenWrt WAN:           192.168.1.250/24
OpenWrt management:    10.77.0.1/24
Proxmox management:    10.77.0.2/24
SMART:                 10.77.20.0/24, VLAN 20, gateway 10.77.20.1
FULL:                  10.77.30.0/24, VLAN 30, gateway 10.77.30.1
```

Если вы повторяете не исходный HomeLab, замените все адреса на свои. Сеть SMART не должна совпадать с сетью FULL, домашней LAN или подсетью Docker.

## Шаг 1. Убедитесь, что DIRECT работает без Proxmox

1. Подключите телефон или ПК к обычной сети Keenetic — не к будущему SMART/FULL.
2. Откройте любой сайт.
3. Выключите VM OpenWrt (если она уже есть) или временно выключите Proxmox только если это безопасно для других сервисов.
4. Снова откройте сайт.

**Должно быть:** обычный интернет продолжает работать. Если нет — сначала исправьте Keenetic/DIRECT. VPN-шлюз нельзя делать единственной точкой отказа для дома.

## Шаг 2. Создайте VM в Proxmox

В панели Proxmox нажмите **Create VM**. Укажите:

| Экран | Что выбрать/ввести |
|---|---|
| General | VM ID: `110` (либо свободный); Name: `openwrt-vpn` |
| OS | импортированный совместимый OpenWrt-образ; не выбирайте случайный ISO |
| System | оставьте стандартное, если образ не требует иного |
| Disks | небольшой диск достаточен; размер зависит от образа и пакетов |
| CPU | 2 cores — подтверждённый исходный пример |
| Memory | 2048 MiB — подтверждённый исходный пример |
| Network | сначала добавьте WAN NIC; остальные добавьте после создания |

После создания откройте VM → **Hardware** → **Add → Network Device** и добавьте management и trunk NIC. Запишите MAC-адрес каждого NIC: по ним вы сопоставите интерфейсы внутри OpenWrt.

Откройте VM → **Options** → **Start at boot** → **Yes**. Не включайте автозапуск до того, как VPN будет проверен, если сервер часто перезагружается без присмотра.

## Шаг 3. Создайте сети в Proxmox

Откройте узел Proxmox → **System → Network**. До сохранения сделайте скриншот текущего состояния или backup конфигурации.

### 3.1 WAN bridge

Это bridge, который уже смотрит в домашнюю LAN Keenetic. В примере он называется `vmbr0`. Подключите к нему WAN NIC OpenWrt. **Не создавайте второй gateway на Proxmox.**

### 3.2 Management bridge

Нажмите **Create → Linux Bridge** и заполните:

```text
Name:       vmbr2                 # пример; проверьте, свободно ли имя
IPv4/CIDR:  10.77.0.2/24          # IP самого Proxmox management
Gateway:    ОСТАВИТЬ ПУСТЫМ
Bridge ports: ОСТАВИТЬ ПУСТЫМ     # изолированная виртуальная сеть
VLAN aware: выключено, если здесь VLAN не нужны
```

Нажмите **Create**, затем примените изменения только если у вас есть локальная консоль Proxmox. Подключите management NIC VM к `vmbr2`.

### 3.3 VLAN trunk bridge

Создайте/настройте bridge для трафика VLAN (в примере `vmbr1`):

```text
Name:         vmbr1
Bridge ports: YOUR_TRUNK_NIC
VLAN aware:   включить
IPv4/CIDR:    оставить пустым
Gateway:      оставить пустым
```

`YOUR_TRUNK_NIC` нельзя угадывать. В консоли Proxmox посмотрите имена:

```bash
ip -br link
cat /etc/network/interfaces
```

Подключите trunk NIC OpenWrt к `vmbr1`; в поле VLAN tag разрешите/передайте `20` и `30` способом, который соответствует версии Proxmox. На физическом коммутаторе и AP те же VLAN должны быть tagged на trunk-портах.

**Должно быть:** после применения сеть управления Proxmox не пропала. Если пропала — вернитесь к консоли и восстановите сохранённую сетевую конфигурацию.

## Шаг 4. Первый вход в OpenWrt

Запустите VM и откройте **Console** в Proxmox. Введите:

```sh
ip -br link
ip -br addr
```

Сопоставьте интерфейсы с MAC-адресами из Hardware VM. Не пишите в документации «eth0 точно WAN»: порядок может отличаться.

В LuCI откройте **Network → Interfaces**.

### WAN

Нажмите **Edit** у WAN → **Protocol: Static address** и заполните:

```text
IPv4 address: 192.168.1.250       # или YOUR_OPENWRT_WAN_IP
IPv4 netmask: 255.255.255.0       # для /24
IPv4 gateway: 192.168.1.1         # или YOUR_ROUTER_IP
Use custom DNS servers: пока не задавайте вслепую
```

Нажмите **Save & Apply**. В Console OpenWrt выполните:

```sh
ping -c 3 192.168.1.1
nslookup openwrt.org
```

**Должно быть:** ping отвечает и имя разрешается. Если нет, не настраивайте VPN: сначала проверьте, что правильный NIC выбран как WAN, gateway верный и адрес не занят.

### Management

Создайте новый интерфейс через **Network → Interfaces → Add new interface**:

```text
Name: management
Protocol: Static address
Device: NIC, подключённый к vmbr2
IPv4 address: 10.77.0.1
IPv4 netmask: 255.255.255.0
IPv4 gateway: ОСТАВИТЬ ПУСТЫМ
```

После применения с Proxmox выполните `ping 10.77.0.1`. Это ваш аварийный путь к OpenWrt.

## Шаг 5. Создайте VLAN 20 и 30 в OpenWrt

В LuCI перейдите **Network → Devices → Add device configuration → VLAN (802.1q)**.

Создайте два устройства поверх проверенного trunk-интерфейса:

```text
Parent device: YOUR_TRUNK_DEVICE
VLAN ID:       20
Name:          YOUR_TRUNK_DEVICE.20
```

и

```text
Parent device: YOUR_TRUNK_DEVICE
VLAN ID:       30
Name:          YOUR_TRUNK_DEVICE.30
```

Затем в **Network → Interfaces → Add new interface** создайте:

| Поле | SMART | FULL |
|---|---|---|
| Name | `smart` | `full` |
| Device | trunk `.20` | trunk `.30` |
| Protocol | Static address | Static address |
| IPv4 | `10.77.20.1` | `10.77.30.1` |
| Netmask | `255.255.255.0` | `255.255.255.0` |
| Gateway | пусто | пусто |

В **Network → DHCP and DNS** откройте вкладку DHCP и добавьте диапазоны (подтверждённый исходный пример):

```text
SMART start: 100, limit: 151       # выдаст .100–.250 приблизительно
FULL  start: 100, limit: 151
```

Проверьте: подключите тестовый порт/SSID VLAN 20. Устройство должно получить `10.77.20.x` и gateway `10.77.20.1`. Повторите для VLAN 30.

## Шаг 6. Firewall: сначала безопасность FULL

Откройте **Network → Firewall → Zones → Add**.

Создайте зоны `smart` и `full`; присоедините соответствующие сети. Для `full` заполните минимальную политику:

```text
Input:   REJECT                 # затем добавьте точечные DHCP/DNS-исключения
Output:  ACCEPT
Forward: REJECT
Masquerading: не включать автоматически
MSS clamping: не включать автоматически
Forwardings: НЕ добавлять full → wan
```

Чтобы клиент получил адрес и мог спрашивать DNS OpenWrt, добавьте правила **Traffic Rules**:

| Название | Source zone | Protocol | Destination port | Action |
|---|---|---|---|---|
| Allow-FULL-DHCP | full | UDP | `67-68` | ACCEPT |
| Allow-FULL-DNS | full | TCP+UDP | `53` | ACCEPT |

ПРОВЕРИТЬ: конкретный интерфейс LuCI для DNS/hijack после включения Nikki может требовать иной port/правило. Сначала добейтесь только DHCP; доступ в интернет FULL до настройки Mihomo не должен появиться.

Для IPv6 у FULL в настройках интерфейса/RA отключите выдачу RA и DHCPv6, пока IPv6 не проведён через VPN и не протестирован.

## Шаг 7. Nikki и Mihomo

Устанавливайте Nikki только по официальной инструкции его разработчика для **вашей** версии OpenWrt. После установки:

1. Откройте LuCI → **Services → Nikki** (название может отличаться).
2. Импортируйте Berendey для SMART и Remnawave для FULL через UI. URL подписок вводите только в локальной панели.
3. Создайте/выберите группу выходов для FULL, например `FULL_VPN_GROUP`.
4. Добавьте пользовательское правило в самый верх списка правил:

```yaml
- SRC-IP-CIDR,10.77.30.0/24,FULL_VPN_GROUP,no-resolve
```

5. Убедитесь, что это правило стоит **выше** правил GEO, rule-set и `MATCH`.
6. Для SMART включите правила Berendey. Не заменяйте их своим списком сайтов без понимания порядка правил.
7. Только если так поддержано вашей версией и это соответствует исходной схеме: TCP — redirect, UDP — TUN.

**Никогда не вставляйте в GitHub экспорт Nikki «как есть»: в нём может быть URL подписки или secret.**

## Шаг 8. Тесты: именно в таком порядке

1. **DIRECT:** подключите обычный клиент Keenetic. Внешний IP — обычный домашний; интернет есть.
2. **SMART:** подключите клиент VLAN 20. Откройте один ресурс, который в вашей политике Berendey должен идти через VPN, и один обычный. Результат зависит от актуальной подписки, поэтому проверяйте журнал Nikki/Mihomo.
3. **FULL при работающем VPN:** подключите клиент VLAN 30. Интернет есть; внешний IP не домашний.
4. **FULL при отключённом VPN:** в Nikki временно отключите только FULL-профиль/группу. Клиент FULL обязан потерять доступ в интернет. DIRECT обязан остаться рабочим.
5. Верните профиль FULL, дождитесь его подключения и повторите тест внешнего IP.

Если на этапе 4 FULL показывает домашний внешний IP — это аварийная ошибка: остановитесь, удалите `full → wan` forwarding, проверьте порядок правила `SRC-IP-CIDR` и перезапустите тест.

## Шаг 9. Как зайти в панели безопасно

В PowerShell на своём ПК откройте туннель LuCI через Proxmox:

```powershell
ssh -N -L 127.0.0.1:18080:10.77.0.1:80 root@YOUR_PROXMOX_IP
```

В браузере откройте `http://127.0.0.1:18080/cgi-bin/luci`. Окно PowerShell держите открытым, пока пользуетесь панелью.

Если API Mihomo слушает только на localhost OpenWrt, используйте:

```powershell
ssh -N -J root@YOUR_PROXMOX_IP -L 127.0.0.1:9090:127.0.0.1:9090 root@10.77.0.1
```

После этого в MetaCubeXD задайте API `http://127.0.0.1:9090`; secret укажите только в локальном приложении.

## Когда нужно остановиться и спросить

Остановитесь вместо экспериментов, если: пропал доступ к Proxmox; неясно, какой физический порт trunk; OpenWrt видит VLAN, но клиент не получает IP; неизвестна версия Nikki; FULL имеет домашний IP при отключённом VPN. В таких случаях приложите в Cursor вывод безопасных команд из [проверки и отката](05-проверка-и-откат.md), без секретов.
