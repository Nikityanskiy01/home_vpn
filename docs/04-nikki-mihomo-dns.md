# 4. Nikki, Mihomo, Berendey, Remnawave и DNS

## Установка и исходная копия

Установите Nikki способом, указанным его официальной документацией для вашей версии OpenWrt. До импорта подписок экспортируйте/сохраните конфигурацию OpenWrt. Не копируйте URL подписки в заметки, скриншоты или Git.

В Nikki добавьте две подписки/профиля: Berendey для SMART и Remnawave для FULL. Названия групп ниже условные.

## Критическое правило FULL

Первым в правилах Mihomo должно стоять правило, которое ловит **всю** сеть FULL и направляет её в группу Remnawave:

```yaml
# ШАБЛОН: синтаксис и имя группы сверить с версией Mihomo/Nikki
rules:
  - SRC-IP-CIDR,10.77.30.0/24,FULL_VPN,no-resolve
  # затем правила Berendey / GEO / rule-set
  - MATCH,DIRECT
```

Замените сеть и `FULL_VPN`. Не ставьте это правило после GEOIP, rule-set или `MATCH`: иначе часть FULL-трафика уйдёт DIRECT.

Для SMART не публикуется универсальное правило: его политика приходит из Berendey/вашего набора правил. В исходной системе именно Berendey определял, что идти через proxy, а что DIRECT.

ПРОВЕРИТЬ: поддерживает ли установленная версия `SRC-IP-CIDR`, точное имя выходной группы и как Nikki сохраняет пользовательские правила при обновлении подписки. Проверьте итоговый runtime-конфиг, а не только экран в LuCI.

## Прозрачный прокси

В подтверждённой исходной схеме TCP обрабатывался `redirect`, UDP — `TUN`. Включайте режимы в Nikki по его документации и тестируйте TCP и UDP отдельно. Не добавляйте `full → wan` как «временную помощь»: этим вы выключите kill-switch.

## DNS без утечек и без поломки VPN

DNS состоит из разных потоков: запросы самого OpenWrt, dnsmasq клиентов, DNS Mihomo и bootstrap DNS для адреса VPN. Bootstrap может быть DIRECT: сначала нужно узнать IP сервера, чтобы поднять VPN. Это не доказывает утечку клиентского DNS.

Настройте DNS в Nikki согласно документации используемой версии и затем проверьте отдельно:

```sh
# На OpenWrt
logread | grep -iE 'dns|mihomo'
nslookup example.com 127.0.0.1

# На FULL-клиенте
nslookup example.com
```

ПРОВЕРИТЬ: адрес/порт локального DNS Mihomo и настройки hijack в Nikki. Не указывайте их в готовом файле без фактической проверки.

## Закрытые панели и SSH-туннели

LuCI можно открывать через Proxmox, не публикуя её в LAN/WAN:

```powershell
ssh -N -L 127.0.0.1:18080:10.77.0.1:80 root@YOUR_PROXMOX_IP
```

После этого откройте `http://127.0.0.1:18080/cgi-bin/luci`.

Если API Mihomo слушает только `127.0.0.1:9090` на OpenWrt, используйте два SSH-прыжка:

```powershell
ssh -N -J root@YOUR_PROXMOX_IP -L 127.0.0.1:9090:127.0.0.1:9090 root@10.77.0.1
```

Тогда MetaCubeXD подключается к `http://127.0.0.1:9090`. API-secret вводится локально в интерфейсе, не в репозитории. В исходной схеме MetaCubeXD располагался в `/www/metacubexd/`; это путь для проверки, не обязательная часть установки.
