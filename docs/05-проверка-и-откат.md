# 5. Проверка и откат

Проверяйте по одному изменению. DIRECT-клиент должен оставаться рабочим на каждом этапе.

## Тесты

| Проверка | Действие | Ожидаемый результат |
|---|---|---|
| WAN | с OpenWrt: `ping -c 3 YOUR_ROUTER_IP` | ответ есть |
| SMART | подключить клиента VLAN 20, открыть нужный и обычный сайт | политика Berendey работает; конкретные сайты зависят от подписки |
| FULL при живом VPN | клиент VLAN 30, проверить внешний IP и DNS | IP VPN, DNS работает |
| Kill-switch | временно отключить профиль/выход FULL в Nikki | у FULL нет интернета и нет DIRECT-IP; DIRECT продолжает работать |
| Изоляция | с FULL попробовать открыть LAN/SMART | доступа нет, если вы его не разрешали |
| IPv6 | переподключить FULL и проверить маршруты | нет обходного глобального IPv6 до отдельной настройки |

Команды диагностики на OpenWrt:

```sh
ip addr
ip route
ip rule
ubus call network.interface.wan status
logread | tail -n 100
nft list ruleset
```

Не фиксируйте «ожидаемый IP» или конкретный тест-сайт в документации: они не подтверждены и меняются.

## Делайте тесты в таком порядке

1. Оставьте один клиент в DIRECT: он показывает, что Keenetic не пострадал.
2. Подключите тестовый клиент только к SMART. Проверьте его IP/gateway и журнал Nikki/Mihomo при открытии сайтов. Конкретные домены определяет актуальная политика Berendey.
3. Подключите тестовый клиент только к FULL. У него должен быть не домашний внешний IP и работающий DNS.
4. В Nikki временно отключите **только** выход/группу Remnawave для FULL.
5. У FULL должен пропасть интернет. Если он всё ещё работает или показывает домашний IP, остановитесь: проверьте отсутствие `full → wan` и порядок `SRC-IP-CIDR`.
6. Верните Remnawave и повторите проверку. DIRECT должен был работать всё время.

## Откат

1. Отключите/удалите только созданные VLAN 20/30 SSID или access-порты, не меняя DIRECT.
2. В Proxmox выключите автозапуск VM110 либо остановите VM, если нужно полностью убрать шлюз.
3. Восстановите backup VM или сохранённый `/etc/config` OpenWrt через консоль Proxmox.
4. Если потеряли доступ к OpenWrt, используйте консоль VM; не пытайтесь чинить firewall по сети вслепую.
5. После отката снова проверьте DIRECT через Keenetic.
